# 7Zipper v0.1.3 검증 기록

검증일: 2026-11-17. Windows 10 Pro 22H2, x64, CP949, 250% 배율.

## 01 / 기존 탐색기 문제 - 임시 설치 경로 잔류

기존 탐색기가 설치 시험용 임시 폴더의 셸 DLL을 계속 보유한 상태 확인. 제거 과정에서 같은 폴더의 실행 파일과 아이콘은 삭제됨. DLL이 자기 위치를 기준으로 두 파일을 찾으므로 현재 등록된 Program Files 경로가 정상이어도 기존 창의 메뉴는 실패할 수 있음.

- 기존 탐색기 프로세스: 삭제된 시험 설치 폴더의 DLL 사용.
- 새 탐색기 프로세스: 정식 Program Files DLL 사용. 사용자 직접 메뉴 선택으로 압축 파일 생성 확인.
- 기존 경로에 검증된 배포 파일을 복구. 같은 구형 DLL의 명령 호출·40px 아이콘 추출·실제 7z 생성·독립 해제 검증 통과. 기존 탐색기 창은 강제로 종료하지 않음.
- 복구 후 기존 탐색기에서도 사용자 직접 압축 성공 확인. 빈 문서 아이콘은 남았으나, Windows에 `SHCNE_ASSOCCHANGED` 갱신 알림을 보낸 뒤 사용자가 같은 창의 정상 아이콘 표시를 확인. 파일 복구와 아이콘 캐시 갱신으로 두 증상 모두 해소.
- 설치 시험에 폐기 환경 지정과 기존 설치 감지 추가. 실제 사용 중인 PC에서 임시 등록·제거를 반복하지 말 것.

기존 셸 단위 시험은 대체 실행 파일로 파이프 전송만 확인했으므로 실제 앱 실행과 기존 Explorer의 DLL 캐시 문제를 검출하지 못함. 이번 검수에서는 등록 경로뿐 아니라 프로세스가 실제로 불러온 DLL 경로도 확인.

## 02 / 배포 앱 - 압축·해제 명령

`shell_installed` 검사에서 실제 셸 DLL의 명령을 호출하고 같은 폴더의 자체 포함 실행 파일 사용. 실행 파일을 시험용 수신기로 대체하지 않음. 등록된 클래식 메뉴·COM 호출과 지정한 배포 DLL 호출을 구분.

| 시험 | 결과 |
| --- | --- |
| v0.1.2 설치본: 클래식 메뉴 API | 앱이 꺼진 상태에서 실제 7z 생성. 외부 7-Zip 해제 내용 일치 |
| v0.1.2 설치본: 등록 COM | 실행 중인 동일 앱으로 요청 전달, 생성·해제 내용 일치 |
| v0.1.3 배포본: 7z 압축 | 실제 앱 시작, 한글·이모지·공백·앰퍼샌드 이름 보존. 외부 7-Zip 해제 내용 일치 |
| v0.1.3 배포본: ZIP 압축 | 동일 앱 재사용. ZIP 서명과 외부 7-Zip 해제 내용 일치 |
| v0.1.3 배포본: 여기에 풀기 | 지정 위치에 두 파일 생성, 43·20바이트 원본 내용 일치 |
| v0.1.3 배포본: 스마트 풀기 | 여러 최상위 항목을 압축 파일 이름의 폴더에 생성. 두 파일 내용 일치 |
| 검증 후 상태 | 시험용 배포 앱만 종료. 정식 설치 등록 유지 |

아이콘 검사: 클래식 메뉴의 실제 HBITMAP과 명령 아이콘을 240 DPI에서 추출. 기존 ICO의 80px·40px 동시 요청에서는 작은 아이콘 누락을 재현했고, 내장 EXE 아이콘에서는 두 크기 모두 확인. 메뉴 등록에도 같은 내장 아이콘 위치 지정.

재현 예:

```powershell
./build/shell/tests/shell_installed.exe artifacts C:/path/to/7za.exe library compress-7z ./artifacts/publish/SevenZipper.Shell.dll
```

명령: `compress-7z`, `compress-zip`, `extract-here`, `extract-smart`. `classic`·`direct` 모드는 현재 설치된 앱을 실제로 실행하므로 진행 중인 작업이 없는 상태에서 사용할 것. 화면 클릭 검증과 API 호출 검증은 구별할 것.

## 03 / 추가 오류 - 재현과 회귀 검사

| 오류 | 수정·검증 |
| --- | --- |
| 종료 대기 창으로 새 요청 전달 | v0.1.2의 요청 누락 재현. 수정본은 사용 가능한 창으로 전달. 정상 창 재사용 유지 |
| 권한·세션이 다른 앱의 통신 충돌 | 실제 Windows 토큰의 SID·세션·권한으로 이름 구분. `CurrentUserOnly` 제한 유지 |
| 폴더별 압축 이름 충돌 | 기존 `A.7z.001` 또는 `A.z01` 옆에서 `A`, `A (2)` 압축. 기존 코드의 이동 오류 재현. 수정 후 두 압축본의 해제 내용과 기존 볼륨 보존 확인 |

- 로컬 관리 코드·작업 프로세스 검사: 120개 assertion 통과.
- WPF 요청 전달·현재 토큰 검사 통과. 셸 CTest 2/2 통과.
- 네이티브 생성·해제·암호·손상·분할·경로 보호·취소 검사 통과.
- 자체 포함 포터블과 Inno Setup 설치판 빌드 통과.
- [Windows CI](https://github.com/yunhyok/7zipper/actions/runs/44034313152): FAT32 포함 128개 assertion, WPF·셸·네이티브 검사, 실제 배포 앱의 네 명령, 폐기 Windows 환경의 설치·업데이트·제거 시험 통과.

## 04 / 설치 시험 - 폐기 Windows 환경 전용

다음 시험은 임시 설치와 제거를 반복하며 셸 등록을 변경함. 일상적으로 사용하는 PC에서는 실행하지 말 것. 기존 설치가 있으면 시험 중단.

```powershell
./tests/shell/installer-smoke.ps1 -Installer dist/7Zipper-Setup-0.1.3-x64.exe -DisposableEnvironment
```

실사용 PC에서 옵션 없이 실행하거나 기존 설치가 있는 경우 등록 변경 전에 중단하는 보호 검사 통과.

## 05 / 미검증 범위

- Windows 11 실기와 관리자·일반 권한 앱의 동시 실기 실행은 미검증.
- 화면 제어 도구의 캡처 시간 초과·입력 실패 발생. 메뉴 API의 비트맵과 명령 검사 결과를 화면 클릭 결과로 간주하지 않음.
- 드래그 입력 자동화 결과는 [v0.1.2 검증 기록](validation-v0.1.2.md) 참조. 이번 버전에서 동일한 드래그 엔진의 전체 실기 검사를 반복하지 않음.
- 4GiB ZIP64·성능 시험은 재실행하지 않음. 코드 서명 미적용.
