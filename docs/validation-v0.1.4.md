# 7Zipper v0.1.4 검증 기록

검증일: 2026-11-19. Windows 10 x64, 시스템 OEM 코드페이지 949.

## 01 / 전체 진행률 - 대기 작업 포함

기존 폴더별 압축·여러 압축 파일 해제는 각 작업 프로세스의 진행률을 같은 막대에 표시. 작업이 바뀔 때 진행률이 바뀌며 대기 항목은 계산에서 누락.

- 정규화·중복 제거 후 전체 압축 파일 수 고정. 아직 시작하지 않은 작업은 0으로 포함.
- 파일별 진행 비율의 평균을 전체 진행률로 표시. **압축 파일 수 기준** 명시. 바이트 크기나 남은 시간 비율은 아님.
- 전체 진행률·완료 개수와 현재 압축 파일의 바이트 진행률 분리.
- 동시 보고를 직렬화하고 파일별 진행 비율은 감소하지 않도록 처리. 암호 재시도도 같은 작업 ID 유지.
- 결과 파일 저장까지 성공한 뒤 완료 개수 증가. 모든 작업 성공 전에는 전체 100% 표시 금지.
- 여러 입력을 하나의 압축 파일로 만드는 경우는 기존 네이티브 전체 바이트 진행률 유지. 추가 디렉터리 순회 없음.

| --- | --- |
| 7z·ZIP·ZIP Zstandard 폴더별 압축 | 6개 폴더, 최대 2개 병렬 작업. 대기 항목 포함·전체 비율 단조 증가·완료 시점 확인 |
| 여러 압축 파일 해제 | 빈 압축 파일과 중복 입력 포함. 정규화 후 7개 작업, 완료 수·해제 내용 확인 |
| 빈 폴더·0바이트 파일 | 작업 완료 개수에 정상 반영 |

| 실패·취소 | 전체 100% 미표시, 미완료 임시 출력 정리, 원본 보호 유지 |

| WPF 종료 상태 | 성공 100%, 취소 문구, 늦게 도착한 보고 무시, 다음 작업 초기화 확인 |

전체 검사 중 기존 드래그 시험의 GUID 버퍼 초기화 누락 발견. 시험용 폴더 이름이 간헐적으로 33자가 되는 현상과 실제 잔류 폴더 확인. 시험 버퍼 초기화 및 32자 검증 추가. 제품의 드래그 구현 변경 없음.

## 02 / 성능 설정 - 스크롤과 작은 창

- 스크롤 내용 아래 24 DIP 여백 추가.
- 성능 설정을 펼친 뒤 레이아웃 계산이 끝나면 입력란이 보이도록 이동.
- 좁은 창의 메모리 한도 설명 줄바꿈.
- 실제 WPF 컨트롤 배치 검사: 내용 영역 400×270, 512×344, 586×730 DIP. 사용자 지정 분할 입력과 성능 설정을 함께 펼쳐 메모리 입력란 표시 및 하단 여유 확인.
- 진행률 내용 영역 520×400, 1060×690 DIP 렌더링 확인. 전체·현재 진행률 겹침 없음.

재현 명령:

```powershell
./scripts/build.ps1 -Test -Publish -Installer
```

릴리스 CI에서 FAT32 검사, 실제 배포 앱의 네 가지 셸 명령, 설치·옵션 변경·제거 검사를 실행. 설치 시험은 폐기 Windows 환경에서만 실행할 것. CI 결과는 해당 GitHub 릴리스의 링크 참조.

## 03 / 검증 범위

- 옵션 창은 실제 WPF 레이아웃과 렌더링으로 검증. 마우스로 스크롤바를 조작하는 실기 시험 및 다중 모니터 간 DPI 전환은 미검증.
- Windows 11 실기, 전체 드래그 실기, 4GiB ZIP64·성능 측정은 이번 변경에서 재실행하지 않음. 이전 검증 기록 참조.
- 코드 서명 미적용. 기본 설치 경로·경로 선택·기존 셸 등록 방식 유지.
